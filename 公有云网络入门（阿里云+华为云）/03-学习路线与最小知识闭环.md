# 03. 学习路线与最小知识闭环

## 1. 先不要追求全懂

公有云网络产品很多，但对初学者来说，不需要一开始就把所有高级功能都学完。更现实的目标是先搭出一个“最小知识闭环”。

所谓最小闭环，就是你至少能回答下面这些问题：

1. 业务资源放在哪个 VPC、哪个子网？
2. 它用私网还是公网通信？
3. 它访问外网靠什么？
4. 外部访问它靠什么入口？
5. 如果另一个网络要访问它，靠什么打通？
6. 如果不通，你先查哪些地方？

只要这 6 个问题能回答清楚，说明你已经不是纯小白了。

---

## 2. 推荐学习顺序

### 第一阶段：先掌握云上网络骨架

先学这几个：

1. VPC
2. 子网 / vSwitch
3. 私网 IP / 公网 IP / EIP
4. 路由表
5. 安全组

学习目标：

- 知道一台 ECS 是怎么放进云网络里的。
- 知道“通不通”主要由什么决定。

### 第二阶段：掌握公网入口和出网能力

再学这几个：

1. NAT 网关
2. 负载均衡
3. DNS

学习目标：

- 知道服务怎么发布给公网用户。
- 知道私网机器怎么安全地访问公网。

### 第三阶段：掌握网络互通

再学这几个：

1. 对等连接
2. VPN
3. 云企业网 / 云连接 / 企业路由器

学习目标：

- 知道两个网络为什么能通。
- 知道多网络组网为什么会复杂。

### 第四阶段：补充安全和高可用

最后补这些：

1. 网络 ACL
2. 云防火墙
3. WAF
4. 多可用区架构

学习目标：

- 知道怎么让架构更稳、更安全。

---

## 3. 推荐你用一张图反复练习

你可以自己手画或用脑图画一个最小架构：

1. 一个 VPC
2. 两个子网
3. 两台 ECS
4. 一个 NAT 网关
5. 一个负载均衡
6. 一个数据库
7. 一个办公网到云上的 VPN

然后反复回答：

- 谁能访问谁？
- 走私网还是公网？
- 经过哪些网络设备或云产品？
- 哪里做安全控制？

这是最快的入门方法之一。

---

## 4. 学习时的正确姿势

### 先学“为什么”，再学“怎么点控制台”

很多人学云只会点页面，但一换厂商就不会了。原因是只记住了操作步骤，没有理解底层逻辑。

你应该优先理解：

- 这个产品解决什么问题
- 它在网络路径里处于什么位置
- 它和其他产品是什么关系

### 多问自己 3 个问题

每学一个产品，都问自己：

1. 它解决什么问题？
2. 它和哪个产品最容易混淆？
3. 如果配置错了，最常见现象是什么？

### 先掌握 80 分，再补 20 分细节

不要一开始就钻特别细的计费、规格、限制、转发模式。先把主干逻辑学会，再补细节更高效。

---

## 5. 给你的厂商学习映射建议

你可以这样学，效率最高：

1. 先学通用概念，不分厂商。
2. 再把阿里云产品名对上去。
3. 再把华为云产品名对上去。
4. 最后在控制台里各自操作一遍。

因为：

- 通用概念才是主干。
- 厂商产品名只是外壳。
- 控制台操作只是最后一层。

---

## 6. 一份适合入门期的记忆清单

如果你现在就想背一版最小清单，记下面这些：

1. `VPC`：云上大内网
2. `子网/vSwitch`：VPC 里的小网段
3. `路由表`：决定去哪里
4. `安全组`：决定让不让过
5. `EIP`：直接对公网
6. `NAT`：统一出网/端口映射
7. `SLB/ALB/NLB/ELB`：对外入口和分流
8. `Peering`：两个 VPC 点对点互通
9. `VPN/专线/云连接`：跨网络互联
10. `DNS`：域名到 IP 的映射

---

## 7. 你接下来可以怎么继续

建议你下一步按这个方式实践：

1. 在脑子里先画出一个最小云上架构图。
2. 试着说出每个组件负责什么。
3. 遇到一个真实业务时，先判断它属于“入口、出网、互通、隔离”哪一类问题。
4. 每碰到一个新产品，都先问它属于这四类中的哪一类。

当你能把任何一个网络产品都归类到这四个方向时，你的学习速度会明显提升。

---

## 8. 最后给你的一个判断标准

如果未来有人问你：

- “这台 ECS 为什么不能访问外网？”
- “这个域名为什么访问不到后端服务？”
- “两个 VPC 为什么还不通？”

你能自然想到从下面这些点去排查：

- 地址
- 路由
- 安全组
- ACL
- NAT / 负载均衡 / VPN
- DNS
- 应用监听

那就说明你的公有云网络基础已经建立起来了。
