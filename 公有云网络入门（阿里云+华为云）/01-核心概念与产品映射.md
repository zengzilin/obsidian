
# 01. 核心概念与产品映射

## 1. 先建立一个总图

可以把公有云网络理解成下面这套关系：

1. 先创建一个大的私有网络空间。
2. 再把它切成多个子网。
3. 云服务器、数据库、容器等资源放进这些子网里。
4. 用路由、安全组、ACL 控制“能不能通”。
5. 用公网 IP、NAT、负载均衡控制“怎么对外提供服务”。
6. 用 VPN、专线、云企业网控制“怎么和其他网络互通”。

你后面遇到的大部分网络问题，基本都逃不开这 6 类。

## 2. 最重要的基础概念

### 2.1 VPC / 私有网络

这是云上最核心的网络边界。

- 阿里云：`VPC`
- 华为云：`VPC`

你可以把它理解成“你在云上独立拥有的一张大内网”。

特点：

- 不同 VPC 默认彼此隔离。
- 你可以自己规划 CIDR 网段，比如 `10.0.0.0/16`。
- 同一个 VPC 里可以继续划分多个子网。

初学者常见误区：

- 误以为 VPC 就是一台服务器。
- 误以为不同 VPC 默认能互通。
- 误以为 VPC 创建后网段可以随意大改。

记忆点：

> VPC 是“云上内网的大边界”。

### 2.2 子网

子网是 VPC 下面更细的网段划分。

- 阿里云：`交换机（vSwitch）`
- 华为云：`子网`

例子：

- VPC：`10.0.0.0/16`
- 子网 A：`10.0.1.0/24`
- 子网 B：`10.0.2.0/24`

为什么要划子网：

- 按业务分层：Web、App、DB 分开。
- 按可用区分布：不同可用区放不同子网。
- 便于隔离和路由控制。

记忆点：

> 子网是“把大内网切小块”。

### 2.3 可用区

可用区不是网络产品，但和网络设计强相关。

- 同城多个机房被划分为不同可用区。
- 高可用部署通常会跨可用区。
- 子网、ECS、负载均衡后端等经常要结合可用区一起规划。

记忆点：

> 可用区决定资源放在哪里，网络决定它们怎么通。

### 2.4 云服务器网卡 / IP

云服务器加入 VPC 后，会获得私网 IP；如果绑定公网能力，还会有公网访问方式。

常见 IP 类型：

- 私网 IP：VPC 内通信使用。
- 公网 IP：对外访问或被外部访问。
- 弹性公网 IP：
  - 阿里云：`EIP`
  - 华为云：`EIP`

记忆点：

> 私网 IP 解决“云内互通”，公网 IP 解决“云外访问”。

### 2.5 路由表

路由决定“发往某个网段的流量下一跳去哪里”。

- 阿里云：`路由表`
- 华为云：`路由表`

常见下一跳：

- 本地子网
- NAT 网关
- VPN 网关
- 对等连接
- 云连接 / 企业路由器

如果你以后排查“为什么不通”，路由是必查项之一。

记忆点：

> 安全策略决定“允不允许”，路由决定“知不知道往哪走”。

### 2.6 安全组

安全组是云服务器级别的虚拟防火墙。

- 阿里云：`安全组`
- 华为云：`安全组`

核心特点：

- 作用对象通常是云主机网卡。
- 以“允许规则”为主。
- 规则常按协议、端口、来源地址控制。
- 既可能影响入方向，也可能影响出方向。

例子：

- 允许 `22` 端口仅办公网访问。
- 允许 `80/443` 给互联网访问。
- 只允许应用服务器访问数据库 `3306`。

初学者常见误区：

- 以为安全组放通了就一定通。
- 忽略出方向规则。
- 安全组规则和操作系统防火墙混淆。

记忆点：

> 安全组更像“绑在云资源上的门禁”。

### 2.7 网络 ACL

这是子网级别的访问控制。

- 阿里云：`网络 ACL`
- 华为云：通常也有类似的 `网络ACL` 能力

和安全组的区别：

- 安全组通常绑实例。
- ACL 通常绑子网。
- ACL 更适合做粗粒度网段控制。

初学阶段你可以先把它理解为：

> 子网门口的大闸机。

### 2.8 公网访问能力

云上服务要被外部访问，通常会涉及下面几类能力：

- 公网 IP / EIP
- NAT 网关
- 负载均衡
- 公网带宽

典型场景：

- 一台跳板机有公网 IP。
- 应用通过 SLB/ELB 对外暴露。
- 内网服务器不绑公网 IP，只通过 NAT 出网下载依赖。

### 2.9 NAT 网关

NAT 是高频考点，也是生产里特别常见的能力。

- 阿里云：`NAT 网关`
- 华为云：`NAT 网关`

常见用途：

- SNAT：让内网服务器主动访问公网。
- DNAT：把公网访问转发到内网服务器。

你可以这样理解：

- SNAT 解决“我怎么出去”。
- DNAT 解决“外面怎么进来找我”。

很多企业会要求：

- 业务服务器不直接绑公网 IP。
- 统一走 NAT 网关出网。

这是为了更好管理、安全审计和带宽集中控制。

### 2.10 负载均衡

负载均衡负责把访问流量分发到多个后端实例。

- 阿里云：`SLB` / `ALB` / `NLB`
- 华为云：`ELB`

你先理解 3 件事就够：

1. 它是对外服务入口之一。
2. 它能把请求分发到多台机器。
3. 它常和健康检查、会话保持、证书绑定一起使用。

常见类型：

- 四层负载均衡：按 IP + 端口转发。
- 七层负载均衡：按域名、路径、HTTP 规则转发。

### 2.11 对等连接

用于两个 VPC 之间互通。

- 阿里云：`VPC 对等连接`
- 华为云：`VPC Peering`

特点：

- 适合少量 VPC 互通。
- 通常需要双方路由都配好。
- 网段不能冲突。

如果 VPC 数量很多，对等连接会越来越复杂。

### 2.12 VPN / 专线 / 云企业网

这是“把不同网络打通”的核心方式。

常见打通对象：

- 本地机房和云上 VPC
- 两个云上 VPC
- 多地域、多账号、多项目网络

常见能力：

- VPN：基于公网加密隧道，成本低，上线快。
- 专线：稳定、低时延，但成本高。
- 云企业网 / 云连接 / 企业路由器：统一做大规模网络互联。

产品名大致对应：

- 阿里云：`VPN 网关`、`云企业网 CEN`、`企业版转发路由器`
- 华为云：`VPN`、`云连接 CC`、`ER 企业路由器`

记忆点：

> 小规模互通看对等连接，跨很多网络互通看云连接类产品。

### 2.13 DNS

DNS 解决“名字怎么找到地址”。

云上常见两类：

- 内网 DNS：VPC 内部解析私网地址。
- 公网 DNS：对互联网解析公网地址。

你以后会经常遇到这类问题：

- 域名解析到公网 IP 还是私网 IP？
- 同一个域名内外网是否分流解析？
- 证书绑定的域名是否和访问域名一致？

### 2.14 共享带宽 / 带宽包

不同云厂商名称略有差异，但核心逻辑相近：

- 多个公网出口共享一组带宽资源。
- 统一做公网成本控制。

### 2.15 云防火墙 / WAF / DDoS

这些属于更偏安全的网络边界产品，但你需要知道基本位置：

- 安全组：实例边界
- ACL：子网边界
- 云防火墙：更上层的统一访问控制
- WAF：Web 应用层防护
- Anti-DDoS：抗大流量攻击

不要把它们都混成“防火墙”。

## 3. 阿里云和华为云产品名称对照

| 能力 | 阿里云 | 华为云 | 你该怎么理解 |
|---|---|---|---|
| 私有网络 | VPC | VPC | 云上内网 |
| 子网 | vSwitch / 交换机 | 子网 | VPC 下的小网段 |
| 云服务器 | ECS | ECS | 放业务的主机 |
| 公网 IP | EIP | EIP | 对外联网地址 |
| 安全控制 | 安全组 | 安全组 | 实例级虚拟防火墙 |
| 子网控制 | 网络 ACL | 网络ACL | 子网级访问控制 |
| 路由 | 路由表 | 路由表 | 决定流量怎么走 |
| NAT | NAT 网关 | NAT 网关 | 出网/入网转换 |
| 负载均衡 | SLB/ALB/NLB | ELB | 对外入口和流量分发 |
| VPC 互通 | 对等连接 | VPC Peering | 两个 VPC 打通 |
| 多网络互联 | CEN/企业路由器 | CC/ER | 多 VPC、多地域组网 |
| VPN | VPN 网关 | VPN | 云下云上加密互通 |
| 域名解析 | 云解析 DNS | 云解析服务 | 名字解析成 IP |

结论：

- 两家云厂商底层逻辑非常接近。
- 初学阶段不要被产品名吓住。
- 你只要先学“能力本身”，再记厂商命名即可。

## 4. 公有云网络里最常见的设计思路

### 4.1 分层设计

一个典型业务会分成：

- 公网入口层
- 应用层
- 数据层
- 运维管理层

对应做法通常是：

- 入口层挂负载均衡或公网入口
- 应用层放私网子网
- 数据层放更严格隔离的私网子网
- 跳板机单独放管理子网

### 4.2 最小暴露原则

原则很简单：

- 能不暴露公网就不暴露
- 能限制来源 IP 就限制
- 能走内网就走内网
- 能分层隔离就不要全平铺

### 4.3 多可用区高可用

不要把所有实例都放一个可用区。

常见做法：

- 两个或三个可用区部署应用节点
- 负载均衡跨可用区转发
- 数据库做主备或集群

### 4.4 网段规划先于资源创建

很多后续问题都源于前期规划差：

- 网段冲突
- 子网太小不够用
- 后面无法和 IDC/VPN/其他 VPC 打通

建议最少提前想清楚：

- VPC 用多大网段
- 每个可用区留多少子网
- 是否未来要打通本地机房
- 是否会多账号、多区域扩展

## 5. 小白必须分清的几组概念

### 5.1 安全组 vs 网络 ACL

- 安全组：更细，贴近实例
- ACL：更粗，贴近子网

### 5.2 公网 IP vs NAT 网关

- 公网 IP：资源自己直接对外
- NAT 网关：资源不直接暴露，也能统一出网或做端口映射

### 5.3 对等连接 vs 云企业网 / 云连接

- 对等连接：点对点
- 云企业网 / 云连接：多点互联，适合规模化

### 5.4 四层负载均衡 vs 七层负载均衡

- 四层：更像端口转发
- 七层：能看 HTTP/HTTPS 规则

### 5.5 路由问题 vs 安全问题

- 路由错了：包不知道去哪
- 安全没放：包到了也被拦

---

## 6. 你现在先记住的最小结论

如果只保留最核心的认知，请记住下面这些：

1. `VPC` 是云上内网的大边界。
2. `子网/vSwitch` 是 VPC 里的小网段。
3. `路由表` 决定流量往哪走。
4. `安全组/ACL` 决定流量能不能过。
5. `EIP/NAT/负载均衡` 决定怎么上公网、怎么对外服务。
6. `对等连接/VPN/云连接` 决定不同网络之间怎么互通。
7. 阿里云和华为云主要是名字不同，设计思路高度一致。
